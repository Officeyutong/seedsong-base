# Music v2: refinement and quality comparison

Version 2 adds integer-only whole-melody pitch refinement after the unchanged
v1 draft generator. It addresses repetitions introduced by chord snapping and
large leaps at snapped notes and phrase transitions. It preserves the melody's
start steps, durations and velocities, and the complete bass, pad and drum
parts. No additional PRNG values are consumed.

The optimizer minimizes deviation from the draft and transition costs while
requiring in-range scale pitches, chord tones on strong beats and phrase
endings, a tonic final note, no triple repeated pitches, and at most 8% large
leaps in each song. Repeated draft motifs can be adapted in their new context;
their exact rhythm remains unchanged. The full normative algorithm and tie
rules are in [spec.md](../../spec.md#58-whole-melody-pitch-refinement-v2).

## Same-corpus comparison

Both versions use the identical 1,000 unique DNA values generated by the fixed
`sng/quality` stream with little-endian indices 0–999. The original report is
preserved in [reports/m1](../m1/README.md).

| Metric | v1 | v2 |
| --- | --- | --- |
| Strong-beat non-chord melody notes | 0 | 0 |
| Out-of-range melody notes | 0 | 0 |
| Ends on tonic | 1,000 / 1,000 | 1,000 / 1,000 |
| Melody note count | 42–121 | 42–121 |
| Large leaps / all adjacent intervals | 3,403 / 79,483 (4.2814%) | 175 / 79,483 (0.2202%) |
| Maximum per-song large-leap ratio | 22.2222% | 4.0816% |
| Three-identical-pitch windows | 999 | 0 |
| `all_targets_pass` | `false` | `true` |

These results demonstrate improved constraint compliance, not a subjective
listening score. On the separate 100-DNA regression corpus, only 458 of 8,197
melody pitches changed: **94.41% of pitches were retained**. Every note's onset,
duration and velocity, and every accompaniment event, remained identical.

## Compatibility and evidence

- [quality-report.json](quality-report.json): all 1,000 v2 rows and actual summary.
- [workspace-tests.log](workspace-tests.log): native test output, including old
  and new regression vectors and the complete 1,000-DNA quality regression.
- [evidence.json](evidence.json): validation outcomes, source fingerprints, stress
  results and artifact checksums for the evaluated working tree.
- Native workspace: 14 tests passed. The JS package build, TypeScript check and
  both Node test files passed. WASM browser tests compiled successfully but were
  not executed in a browser. Clippy passed with warnings denied.
- An extended 10,000-DNA run also met every target: zero triple-repeat windows,
  zero strong-beat non-chord or out-of-range notes, and a maximum per-song leap
  ratio of 5.8824%. Its summary and reproducible command are in `evidence.json`;
  the extended raw report is not archived here.
- `vectors/music-v1.json` was not regenerated. All 100 legacy vectors still pass.
- Regenerating the old 1,000-DNA report with `--music-version 1` reproduces the
  original report byte-for-byte. One-thread and four-thread v2 reports also
  match byte-for-byte.

The music version is explicit: SNG1 header byte 4 is now 2 by default. Legacy
Rust callers use `Song::generate_with_version(..., MusicVersion::V1)`, CLI users
use `--music-version 1`, and JS callers use `musicVersion: 1`. WAV results expose
`musicVersion`; CLI JSON sidecars record the specification identifier.
The unchanged v1 specification is archived in [spec-v1.md](../../spec-v1.md).
The Rust crates and JS package are version 0.2.0.

The SVG pattern and displayed DOB traits are unchanged. New music artifacts
must be referenced as `seedsong-music/2`; existing Clusters must keep their
original version and decoder reference. The UI repository still pins its own
submodule commit and must be updated after this change is committed. Any UI
metadata hardcoded to `seedsong-music/1` should also be updated, and saved tracks
must include the returned music version.

## Reproduce and listen

```bash
cargo test --workspace
cargo run --release -- --check 1000 --threads 4 --report /tmp/seedsong-v2-check.json
cargo run --release -- --music-version 1 --check 1000 --threads 4 \
  --report /tmp/seedsong-v1-check.json
cmp reports/m1-v2/quality-report.json /tmp/seedsong-v2-check.json
cmp reports/m1/quality-report.json /tmp/seedsong-v1-check.json
npm run test:js
```

Use new output paths when rerunning: the CLI intentionally does not overwrite
files. For listening, compare identical DNA, timbre and render settings:

```bash
cargo run --release -- --music-version 1 \
  --dna 5bf48d079c2680dd2a20fa36cb9e699caf567174410030c762975c0ff503ee31 \
  --timbre piano --reverb 0 -o /tmp/seedsong-before.wav
cargo run --release -- --music-version 2 \
  --dna 5bf48d079c2680dd2a20fa36cb9e699caf567174410030c762975c0ff503ee31 \
  --timbre piano --reverb 0 -o /tmp/seedsong-after.wav
```

Manual listening and browser playback were not performed for this comparison.
The remaining M1 demo and listening acceptance work is separate from these
objective results.
